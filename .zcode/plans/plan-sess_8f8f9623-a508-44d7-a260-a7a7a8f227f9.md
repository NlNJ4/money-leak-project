LINE webhook, Gemini parsing, and account linking (Phases 4–7) come in the next pass. Each step ends with a commit + push to `origin/main` (your standing rule).

## Step 2 — Database schema + RLS (Supabase MCP migrations)
Follow the supabase-postgres-best-practices skill. Migrations applied to `money-leak` (gzpkjxzjocrgnsmpaeug), plus committed as SQL files under `supabase/migrations/`:
1. **categories** — `id`, `slug` (unique), `name_th`, `name_en`, `type` (`income|expense`), `icon`, `sort_order`; seed the spec's fixed enum (§7): 9 expense (food 🍜, transport 🚕, shopping 🛒, housing 🏠, bills, health, entertainment, family 👨‍👩‍👧, other) + 5 income (salary, freelance, investment, refund, other_income). Read-only for users (global reference table).
2. **user_identities** — `id`, `user_id` → `auth.users`, `provider` (`google|line`), `provider_user_id`; unique `(provider, provider_user_id)`; index on `user_id` (spec §8).
3. **transactions** — `id`, `user_id`, `type` check (`income|expense|transfer`), `amount` numeric > 0, `currency` default `'THB'`, `category_id` FK, `description`, `transaction_date` date, `source` check (`line|web|receipt`) default `'web'`, timestamps; indexes `(user_id, transaction_date desc)` and `(user_id, category_id)`; `updated_at` trigger.
4. **RLS** — enable on all tables; users can CRUD only their own rows (`user_id = auth.uid()`); categories = SELECT for authenticated.
- Generate `types/database.types.ts` via MCP so queries are typed.

## Step 4 — Google auth
- `app/auth/callback/route.ts` — `exchangeCodeForSession`; `app/auth/signout/route.ts`.
- `app/login/page.tsx` — "Sign in with Google" (server action `signInWithOAuth`), bilingual copy.
- `app/page.tsx` — redirect to `/dashboard` when logged in, else `/login`.
- Dashboard guard — server-side user check, redirect to `/login`.
- **Your action (one click):** in Supabase dashboard → Authentication → Providers → Google: enable and paste your Google OAuth client ID/secret. I'll give exact instructions when we reach this step.

## Step 5 — i18n (Thai + English, switchable)
- `lib/i18n/dictionaries.ts` — `th` + `en` dictionaries covering all UI strings (default **th**).
- `lib/i18n/provider.tsx` — client context provider; language persisted in a cookie so the server can SSR the right language; toggle button in the dashboard header.

## Step 6 — Transaction service + API
- `lib/categories.ts` (static list mirroring DB slugs, with i18n names + icons), `lib/validation.ts` (zod schemas: type, amount > 0, approved category, date — spec §12), `lib/format.ts` (฿ formatting, Thai date).
- `lib/transactions.ts` — create, list with filters, month totals, category breakdown, recent.
- `app/api/transactions/route.ts` — GET (list + filters) and POST (validated create), authenticated via Supabase server client.

## Step 7 — Dashboard UI
`app/dashboard/page.tsx` (server component fetching current-month data) + client components per spec §15:
- Month summary cards (Income / Expense / Net), category breakdown with icons, recent transactions list, add-transaction form (type/amount/category/description/date), period filter (today / this week / this month / custom range), language toggle.

## Step 8 — Verify
- `pnpm lint` + `pnpm build` green; run dev server and verify the full flow (login → add transaction → appears in summary/filters → language switch persists) in the browser.
- Final commit + push.
